### 第八轮：代码推上 Gitee（第七轮的延续）
- **Gitee 已推通**：用户在网页端建好空仓 `chenhuanjin/sketchsmith`（公开）后，`git push -u origin main` 一次成功，**114 个文件全部到位**（index.html / README.md / LICENSE / src/main.js 均确认在远端）。
- **为什么之前推不了**：本机 `~/.git-credentials-gitee` 里两条令牌都是**仓库级私人令牌**，绑定在某个别的具体仓库上。决定性证据不是建仓那条报错，而是 **`GET /v5/repos/chenhuanjin/sketchsmith` 直接返回 404** —— 这个令牌连看都看不到新仓，所以任何针对 sketchsmith 的 API 操作（含开 Pages）必然失败。**推代码走 SSH 不受影响**（`ssh -T git@gitee.com` → `Hi chenhuanjin`）。
- **结论/以后直接照做**：Gitee/GitHub 的**push 一律走 SSH，别用令牌**；但**任何跨仓库的管理类操作（建仓、开 Pages、改设置）必须用户在网页端点**，或者给他一个**针对该仓新生成的令牌**。仓库级令牌 ≠ 账号级令牌，别再拿它试需要账号权限的事。
- Pages 端点实测：`GET/POST/PUT /v5/repos/{o}/{r}/pages` 全部 **405**，`/pages/build`、`/pages/builds` 均 **404**——不是参数写错，是令牌根本到不了这个仓。
- 仓库状态实测：匿名可见（`private:false, public:true`），主页 http=200 / 0.57s，raw 的 `index.html` 返回 302（Gitee raw 正常签名跳转）。
- **Pages 尚未开通**：`https://chenhuanjin.gitee.io/sketchsmith` 目前 404。需用户在 https://gitee.com/chenhuanjin/sketchsmith/pages 点一次「启动」（部署分支 main、目录 /、勾强制 HTTPS）；可能要求实名认证；且 Gitee Pages **每次推新代码后要手动点「更新」才会重新部署**（不像 GitHub Actions 自动）。
