### 第八轮：代码推上 Gitee（第七轮的延续）
- **Gitee 已推通**：用户在网页端建好空仓 `chenhuanjin/sketchsmith`（公开）后，`git push -u origin main` 一次成功，**114 个文件全部到位**（index.html / README.md / LICENSE / src/main.js 均确认在远端）。
- **为什么之前推不了**：本机 `~/.git-credentials-gitee` 里两条令牌都是**仓库级私人令牌**，绑定在某个别的具体仓库上。决定性证据不是建仓那条报错，而是 **`GET /v5/repos/chenhuanjin/sketchsmith` 直接返回 404** —— 这个令牌连看都看不到新仓，所以任何针对 sketchsmith 的 API 操作（含开 Pages）必然失败。**推代码走 SSH 不受影响**（`ssh -T git@gitee.com` → `Hi chenhuanjin`）。
- **结论/以后直接照做**：Gitee/GitHub 的**push 一律走 SSH，别用令牌**；但**任何跨仓库的管理类操作（建仓、开 Pages、改设置）必须用户在网页端点**，或者给他一个**针对该仓新生成的令牌**。仓库级令牌 ≠ 账号级令牌，别再拿它试需要账号权限的事。
- Pages 端点实测：`GET/POST/PUT /v5/repos/{o}/{r}/pages` 全部 **405**，`/pages/build`、`/pages/builds` 均 **404**——不是参数写错，是令牌根本到不了这个仓。
- 仓库状态实测：匿名可见（`private:false, public:true`），主页 http=200 / 0.57s，raw 的 `index.html` 返回 302（Gitee raw 正常签名跳转）。
- **Pages 尚未开通**：`https://chenhuanjin.gitee.io/sketchsmith` 目前 404。需用户在 https://gitee.com/chenhuanjin/sketchsmith/pages 点一次「启动」（部署分支 main、目录 /、勾强制 HTTPS）；可能要求实名认证；且 Gitee Pages **每次推新代码后要手动点「更新」才会重新部署**（不像 GitHub Actions 自动）。

## 第八轮：三种声音风格真正可辨（D31）+ 关2 难度实测（2026-10-30 夜）
- **用户实测「选 3 个声音没有差异」＝ 真 bug**：`SOUND_THEMES` 里 musicbox 与 ocarina 的 `wave` **都是 sine**，只差 5% 音量；试听音又是 0.18s 的 `ability` → 连 warm(三角) 与 sine 都听不出。**教训：把音色差异做在"配置表字段不同"上不算数，必须在真实发声路径上可测。**

- `startVoice` 支持泛音声部（每条独立包络，衰减快于基频）；`playArp` 透传 partials/filter/noteDur；`AUDIO_NODE_BUDGET` 40→56（单音最坏 7 节点 × 8 并存）。
- 新增 `preview` 试听音（4 音琶音、单音 0.62s）替掉 0.18s 的 ability。
- 新增 `tests/sound-theme.mjs` 5/5：假 `AudioContext` 捕获真实发声路径，断言 osc 条数/泛音比/起音/滤波两两不同 + 共享配方表未被污染。

## 第九轮：关2 难度重标定（D32）+ 二次发布（2026-10-30 深夜）
- 用户反馈「第2关很容易过，是不是把箱子推到坑里也能过」。核实：**不是判定 bug**（`checkGoal` 只读 `props[activeProp]` = 南瓜，造物自己进坑不判过）；但**"太容易"是真的**：x=195(悬空26px) 时 20 投 19 过，连 t=5 软梁都 3/3 顶下去。
- **否掉用户的字面方案并给出证据**：南瓜挪回岸上（完全平放 x=165）实测 **质量 13.45 与 6 都是 0/4 全失败** —— 造物垂直下落对平放箱体无水平推力（与文档早年 0/25 一致）。这条路是把关卡做过不去，不是变难。
- **采用**：悬空 26→21px（重心 195→190）。四约束交点：26px 5/5+梁WIN / 24px 4/5+梁WIN / **21px 3/5+梁WIN（采用）** / 17px 1/5+梁timeout。副作用正向：静置漂移 0.08px。
- **学到的一条**：旧判据 1b「任何投放都必须落进终态」与关卡规则 6「仍悬空→不判」**本身就矛盾**，过去只因"连软梁都能顶下去"而永远有终态，矛盾被掩盖。判据改为「终态 或 仍悬空(right>200)」，即**无死态**。
- **能力公平性**：`会滚` 在悬空带右端会冲过头卡右侧石头。逐点扫描（`tools/probe-l2-window.mjs`）得「变硬/变硬+会滚」**共同可过带 206..216**，判据采样窗据此定在带内。
- 冒烟配套：关2 解法改 **206→300 t=9**（长梁 182→356 在新几何下 timeout）；重来回归改用**关1**（合成笔画落点不可控，只把南瓜推了 3px）。
- 验证：`l2-acceptance` **0 未达标**、l2-verdicts 7/7、core 20/20、build 430,579B、smoke 全通。
