## 三、这一轮真的做了什么

1. **单文件构建**：`tools/build.mjs` 先探测 esbuild，没有则走 `tools/bundle-fallback.mjs`（约束拼接器：只允许单行具名 import、具名 export、顶层名全仓库唯一、DAG 无环）。**本机没有 esbuild，所以产物走的是兜底路径**（未压缩，262KB，仍在门禁内）。
2. **形态判定 S1–S12**：采样（2px / 400 点）→ RDP ε=1.2 → 闭合检测 → 几何属性 → 十序判定树（序 2 绳按 D11 不实装、序 2b 双笔细长判梁）→ 凹多边形分解 → 刚体生成。
3. **三级退化 + NaN 守卫**：分解 → 凸包 → AABB → 圆；每 10 帧 `NaNGuard.sweep` + 速度钳制。`?debug=1` 里 `degraded` 会如实显示。
4. **能力骨架**：纯数据记录（`mods` / `hooks` / `flags`），无 24 连 if-else。本轮实装 5 个：变硬 / 会滚 / 变重 / 变轻 / **怕痒（tickle，D15 冲量钩子）**；其余 19 个只有名字表。
5. **最小音频**：1 个 `AudioContext`（单例 `AudioBus`），**10 个程序合成音效**（pendown/spawn/ability/win/fail/stamp/collide/ui + 关4 弹射 `spring` + 关5 落水 `water`）+ 1 层五声 BGM 垫音（lookahead 调度）+ 语音；**无中文语音时自动降级成气泡**，不会拿英文嗓音念中文；首次 `pointerdown` 同步解锁（iOS）。
6. **碰撞音聚合**：物理侧每帧跨子步取 `score = |vRel| × mEff` 最大者回调一次（静态体 `mEff` 用另一方质量，避免 `Infinity` 传染 NaN），带最小分闸门 + 同 pair 90ms 冷却。
7. **存档抽象层**：core 只依赖 `SaveStore` 四个方法（read/write/list/migrate），唯一实现 `src/platform/local-storage-save-store.js`；`file://` 下 localStorage 不可用时自动退化内存桩，绝不阻塞启动。v1→v2 迁移有单测（幂等、不丢数据）。

## 五、与设计案的偏差（必须知道）

1. **关2 已按新案重建（B 版 + D22 落位），但两条教学设计实测不成立（见 5.1）**。新几何：两岸等高（台面 y=300）、中间 200..330 深沟、沟底收货口 205..285、南瓜 62×62 重心 x=195（悬空 26px ≈42%）。撬杠、短坡、两级台阶、台沿矮唇、夹槽支点全部未建（`tests/lever.mjs` 是"为什么不做撬杠"的反证留档：力矩够但梁架在单块石头上会翻，加夹槽又把转角夹到 0.8–3.3°、南瓜永远进不了集市）。
2. **旧机制的原始偏差记录（保留）**。`levels.md` 的三条参考解法都以「南瓜滑/滚起来」为前提。实测 `matter-js` 的摩擦求解器（`tests/probe2.mjs` 全部实测数据）：
   - `pair.friction = min(a,b)`、`pair.frictionStatic = max(a,b)`，求解时两者**相乘** → 接触对里只要有一方 `friction > 0`，切向相对速度就被清零。0.05 与 0.9 的停止距离**都是 ≈8px**。
   - 只有 `friction = 0` 才滑得起来；而 `friction = 0` 的滑行体**任何 ≥5px 的台阶都会把它彻底卡死**（实测 5px 就停、9px 还会往回滑）。
   - 所以「平地架桥让南瓜滑过去」在本引擎里必然卡在桥面比岸面高出的那一个梁厚上，不是调参能救的。
   - 改成：南瓜 `friction = 0` 自己慢慢滑 → 滑出高台（落差 60px）→ 玩家在沟里架桥（两头搭两岸，桥面必然低于高台）→ 滑到集市。**全程只向下，没有向上的台阶**。教学点从「形状决定形态」偏向「强度」（软梁接不住 13.4kg）。
   - 代价：`会滚` 在关2 成了干扰芯片；`轮/雪橇` 两条参考解法不可实现。已同步反映在 `failHints` 与本表。

### 5.1 关2 的判定：一条判定 + 四序终态 + 两句台词（D24/D25/D26）

判定只有一条：**南瓜在非收货口区域停止推进并静止 → 失败**。位置不决定"判不判"，只决定"说哪句"。
顺序是硬要求（进收货口的南瓜同样是静止的，先判静止就会把 win 判成 fail）：

| 序 | 位置 | 判定 | 台词 |
|---|---|---|---|
| 1 | 进收货口 205..285 | **win** | `l2_win` |
| 2 | 到沟底（y≥400）但落在口外 | 碎 | 失败暗示阶梯 |
| 3 | 完全退回岸台面（右缘 ≤ 200） | fail | `common_fail2` |
| 4 | 停在造物顶面 | fail | `common_fail2` |
| 5 | 卡在沟壁（320 < y < 400） | fail | `common_fail2` |
| 6 | **仍部分悬空 + 静止** | **不判任何终态** | —（这是正常初始态，也是"擦碰 100px 也不判"的根） |

- **静止口径**：`|v| < 0.2 px/帧` 且 `|ω| < 0.02 rad/帧`，**连续 90 帧**（1.5s）都低 `[待实测标定]`。窗口内每帧都判，不是比首末两点（否则"被慢慢推着爬"会被判成静止）。
- **不用位移门槛**（D25）：判"还能不能推进"靠位置，不靠"动了多少"。造物垂直落下给不出向右的水平推力，所以右缘退回台沿以内 = 推不回来了 = 不可推进；反之擦碰 100px 也不判失败。
- **失败不销毁旧南瓜**（D26）：旧那颗留在停下的地方，只在原位再长一颗（`tests/l2-verdicts.test.mjs` 断言场上 ≥2 颗）。
- 判定表本身有 7 条构造式单测（`node --test tests/l2-verdicts.test.mjs`，7/7 过），**和"能不能在玩法里碰上"是两件事**。
- **同句台词 ≤2 次**（附录 A），两个粒度：**整局**（形态台词、各关专属失败暗示）/ **每关**（跨关通用兜底句 `common_fail2`，进关 `reset()`）。
  兜底句必须按每关计——它是"任何没预料到的终态都还有一句话"的安全网，整局额度被前一关吃光，关3..关9 就只剩余光和静默。
  第 3 次起静默由"悬空半边发光 / 轮廓虚线"接手，**绝不许补同义句**（换句会被读成"判定变了"）。
  **扣额度的时序**：`exhausted()` 只查不扣、`take()` 在真正交付之后才扣（对齐 `audio-spec-v2` §583–585 的顺序：C5 → 只读配额预检 → C4 延后 → 起播才扣）。被音频层拦下的一次都不许扣，否则整局 2 次额度会被"没播出去"的句子烧光。
  配额是纯函数 `createLineQuota(max)`（带 `reset()` / `exhausted()` / `take()`），粒度由 `isPerLevelLine(id)` 判定，两者都有单测：
  `[true,true,false,false]` + "进关 reset 后又能说 2 次" + "被拦下的那次不扣"——**粒度与时序改错都必须能被测试抓住**，而不是等人发现关3 以后没台词。

**两处真问题（本包修掉）**：
1. 早先 `prop-stalled`（3 秒不动 = 失败）在新关里把**正常初始状态**判成失败，而南瓜被顶到岸上之后它又不报——两头都错。已删掉那条 stall 判据，换成上面这条位置判定。
2. 梁落下后**既不 win 也不 fail**（软锁）。1b 判据现在 6/6 有明确终态，零次"都没有"。

**两个终态实测不可达 ⇒ 专属台词已连 id 一起删除（不是"预留"）**：
- `prop-back-on-bank`（岸台面）：26 次真实运行 **0 次**。根因是**没有任何东西能把它往左推**——所有造物只往下落，能给的只有"向下 + 向右"的冲量。这个状态在物理上**不存在**。
- `prop-on-creature`（造物顶面）：**0 次**。南瓜落进沟里时，要么还在口内（win）要么卡沟壁，中间没有"干净地站在造物顶上"的窗口。
- 曾为这两个终态写过 `l2_fail_beam` / `l2_fail_ontop` 两句台词，**已删**（连 id）。理由：不可达的台词等于没有台词，留着是 `ch1_stamp` 那类静默 bug 的温床。断言反过来锁死——谁再加回来就红。
- `prop-on-creature` 已登记为 **1.1 后迭代**：等真的做出"南瓜落在自己搭的东西上"这个中间态，再连机制一起加台词。**判定分支保留**（构造状态下 3/3 命中），所以加台词只是加一句文案。

**D26-1 的答案（轮能否把退回岸上的南瓜顶回来）：测不出。**
构造状态（南瓜重心 150、右缘 181、距台沿 19px），轮从左侧来，4 种能力组合 × 4 个落点共 16 次：南瓜最大位移 **8px**（右缘 181→189），16/16 都没过台沿。⇒ 按 D26 的口径，`prop-back-on-bank` **保留 fail**。

### 5.2 被作废的两条判据（不是放宽，是互斥）

一条几何事实：**方南瓜绕台沿棱翻倒的势垒 = 重心到棱的距离 r 减去半高 31**。
悬空 26px（重心 195）时只剩 **0.40px** 的重心抬升；悬空 31px 当场翻；不悬空（重心 165）是 15.75px。

- **判据 1（梁碰不到南瓜）**：跨沟的梁必须穿过 200..226 这一列，而 200..226 正是南瓜悬空的半边。要让南瓜零位移，它必须整块在 178 左边 ⇒ 一定不悬空 ⇒ 一定推不动（实测 **0/25 胜**）。加岩檐能修好判据 1（0.57/0.31px），但只在 196..226 留 30px 的口，造物直径 ≥40px ⇒ 真解掉到 1/5。**没有中间解。**
- **判据 7（不点变硬必须失败）**：`变硬` 不改质量。势垒 0.40px ⇒ 冲量和持续压没差别。质量 13→120 扫了一遍，**全程没有"硬过、软不过"的窗口**（13–50 软造物照样过；65 以上两者都 0/5）。
- 根因一句话：**「无机关 + 只允许竖直下落」只能给冲量；冲量推不动真实的势垒；而势垒≈0 时任何东西都推得倒。**
- 设计侧裁定（D23）：判据 1/7 作废，**梁是第三条真解**，关2 改教「落点」，成为全作唯一的"不靠能力"关。
3. **`ENABLE_ROPE=false`（D11）**：判定树序 2（绳）整条不写，没有 `freezeChain`。`body-factory` 里的 rope 分支仍保留但当前判定树不会产出 rope。
4. **`?debug=1` 是唯一标定依据**：所有阈值仍带 `[待实测标定]`，没有按个人手感定死。
5. **音频 P0 之外没做**：22 个 SFX 里只做了 6 个 + `collide`/`ui` 两个补充；机关/环境音（压板/感光/沙漏/水/火/岩浆）未做；`setVolume` 只做了最小实现；`x`（立体声定位）忽略。

## 五之二、`会滚`（D16）：不改摩擦，只压空气阻尼

`friction`/`frictionStatic` 一旦非 0，matter 的摩擦求解器就会把切向速度清掉——所以"降摩擦"换来的不是滚，是"既不打滑也不滚、被任何 5px 台阶卡死"，名字和实现相反。`frictionAir` 每个子步同时衰减 `velocity` 与 `angularVelocity`，压低它 = 抓地还在 + 滚得更远，不需要额外扭矩。

- 实现：`CREATURE_ROLL = { frictionAirMul: 0.25 }`（乘算键，与 `变重` 可交换）；`body-factory.applyMods` 里 `frictionAir = 基线 × 0.25`
- 验收：`node tests/roll.test.mjs`（11 条断言）
  - `friction` 0.05 → 0.05，`frictionStatic` 0.08 → 0.08（一个数没动）
  - 8° 斜面 3 秒：裸圆 65px/1.5 rad → 会滚 **100px/2.9 rad（×1.55）**
  - 长条贴会滚：9px → 10px（**差 11%**）= 形状不对就基本没意义
  - 被否决的 `friction=0` 留证：平地滑 292px 但只转 0.08 rad（真滚应转 11.2 rad）= 雪橇，不是滚

## 五之三、语音排队与配额（`audio-spec-v2` C.1 / C.1b / C.2）

语音的排队/配额抽成**纯逻辑** `src/audio/voice-scheduler.js`（不碰 `speechSynthesis`、时钟注入），
这样"五步优先序"才能被单测逐条数出来——否则只能靠读代码相信。

**C.1 五步（顺序写死）**：① C5 说话人不在画面内 → **挂起**（不扣、不丢）→ ② 配额**只读**预检（不够就出队，
连 C4 延后都不做）→ ③ C4 同音色 45s → 延后 → ④ 超时丢弃 → ⑤ `onstart` **扣 1 次（全程唯一扣费点）**。
> 为什么不能只在 ⑤ 查额度：会出现"C4 已延后 30 秒 → 到点发现额度没了 → 丢弃"，玩家白等。

**C.1b 抢占 ≠ 终止**：`dropPending()` 只摘尚未起播的（**不扣费**）；`abortSpeaking()` 停已起播的（**已扣不退**，
否则能刷额度）。切关/说话人离场/事件已过去必须终止——否则玩家已在新关卡、耳朵里还在念上一关，音画脱钩会被当 bug 报。
队列上限 1 在播 + 1 等待；队满时丢"尚未起播的最低级别"，**同级别不换**（先到先等，避免同级颠簸）。

**C.2 两套额度不许混**：`sayCapped` 是**文字出现次数**（整局 2 / 每关 2），`voice-scheduler.budget` 是**语音额度**
（整局 ≤30 条 / ≤75 s）。混用会"文字把语音额度吃光"，症状是**字幕全出来了却一句都没念**——看起来像语音坏了，
排查会先去查 `getVoices()`，方向全错。

**实测自检（`node --test tests/voice-scheduler.test.mjs`，10/10）**
- 没起播不扣；C5 挂起期间不扣、入画后只扣 1 次；C4 延后 44 秒不扣、到点只扣 1 次；
- 已起播被打断：额度不回滚；抢占未起播：一次都不扣；
- 队满只丢"尚未起播的最低级别"，受额度约束的等待句不许被抢；
- 20 次纯文字台词后语音额度仍是满的（30/30）；
- 全仓库 `speechSynthesis.cancel(` **只有 1 处**（audio-bus 的 `voiceBackend.cancel`），由断言守住；
- 台词级别按**时机**推（`lineVoiceLevel`），不逐句手标——避免"这句写得重要所以不给抢"这种主观判断。

**一处实现取舍**：TTL 从"它本来可以起播"那一刻算起，不是从入队算起。否则 TTL 与 C4 同为 45s 时，
被 C4 延后的句子会在刚够格的同一刻被判超时，C4 永远不可能成功——这个 bug 是单测里真撞出来的。

**未完成**：`isOnScreen` 目前恒为 `true`（关卡还没有镜头推拉），C5 因此不会被真实触发；
等有相机可视区再改 `main.js` 里那一个函数即可（C.5 唯一需要动主程序的地方）。

## 七之二、一次真实的静默 bug（复盘：`ch1_stamp`）

第 1 章通关印章**从来没有播过**。`src/level/levels/ch1-03.js` 里写的是 `stamp: 'ch1_stamp'`，而台词表里的 id 实际叫 `stamp1`——JS 对象不会因为引用了一个不存在的字符串键报错，运行时 `lines[stamp]` 拿到 `undefined`，播放函数就安静地 return 了。没有异常、没有 console.error，只有"玩家永远看不到那一句话"。

它是怎么被抓到的：给台词表加了一条**闭集断言**（`tests/core.test.mjs`）——6 个 `form_*` id 必须全部存在，且**每一关 `lines` 里的每个槽位 id 都必须在表里**。第一次跑就红了。

值得记住的不是这个 typo，而是**这类 bug 只能靠"闭集断言"抓**：任何"字符串键指向另一张表"的地方（台词、音效、印章、成就、成就图标）都该有一条"所有引用都能解析"的测试。之后新增台词槽位时，这条断言会先红，而不是等玩家告诉你"通关没反应"。
