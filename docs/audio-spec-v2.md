## 一、三层结构总表

| 层 | 唯一职责 | 承载信息 | 触发者 | 形态 | 可否单独关 | 体积 |
|---|---|---|---|---|---|---|
| **BGM** | 告诉玩家「现在在哪一章、什么心情」 | 章节身份 · 情绪基线 · 压力有无 | 关卡状态机 | 持续，无 loop 点，实时生成 | 可 | 0 KB |
| **SFX** | 告诉玩家「这一下有多重、成没成」 | 因果反馈 · 物理重量 · 机关状态 · **能力组合奖励** | 每个游戏事件 | 一次性 | 可 | 0 KB |
| **语音** | 只负责「情绪高点的人格化」——好笑、被盖章、收束 | 幽默 · 里程碑 | v2 六类时机 + 冷却闸门 | 一次性，全局限量 | **可**（独立于 BGM/SFX） | 0 KB（系统音库） |

### 职责边界（不许越界）

| 禁止 | 原因 |
|---|---|
| **台词不做教程朗读** | v2 9.1 已裁定：教程/操作提示/芯片说明/提示阶梯第 2、3 级一律纯文字。成人被念三次就关声音。 |
| **SFX 不做情绪评价** | 音效只说「发生了什么」。赞美是语音的独占职责。 |
| **BGM 不随单次操作变** | 逐笔响应 = 噪音墙。BGM 只认章节与压力状态，不认单次成败。 |
| **语音不做倒计时播报** | 时间压力只由 `sfx_hourglass` 与画面承载。 |
| **不朗读屏幕上已有的长文本** | 长版台词是给成人读的笑点，念出来会拖成两口气，笑点必碎。 |
| **不做滑稽音效** | 无屁声、无滑稽下滑音。全年龄，且会廉价化整个作品。 |
| **SFX 不追求写实** | 纸感画风 + 写实音 = 违和。全部做「乐器化」抽象音。 |
| **不用英文声音念中文** | 无 `zh-*` 时进气泡模式。怪声比静音更糟，6 岁完全听不懂。 |

## 二、BGM 规格

### 2.1 总原则

| 项 | 规定 |
|---|---|
| 生成方式 | **实时音符调度**（lookahead scheduler），**不使用 AudioBufferSource 循环**。无 loop 点 = 天然无「8 秒腻」。 |
| 音阶 | 五声音阶（宫商角徵羽），无半音、无导音 → 6 岁听着不刺耳，成人听着不幼稚 |
| 声部 | ① 垫音 pad（长音铺底）② 低音 bass（段落锚点）③ 动机 motif（唯一有旋律感的层） |
| 和声写法 | 只给**根音 + 五度**（省三音）→ 空、留白、不像流行歌、不像游戏 BGM |
| 拍速 | ♩= 60–96 `[待实]`；「慢慢来」开启时全章降档 `[待实]` |
| 音色基底 | 三角波（温）+ 正弦（净）+ 极少量方波（硬边，仅第 2 章）；全部经一个低通 BiquadFilter |
| 噪声层 | 预生成 **1 s 白噪 buffer 复用**（不每次 new）→ 带通 → 纸/风/翻页 |
| 响度 | 恒定，不做随关卡的整体音量抬升。压力靠密度与音区，不靠音量 |

### 2.2 三章音乐性格差异（差异落在哪个参数上，不是「更紧张」）

| 参数 | 第 1 章 · 造物实习期 | 第 2 章 · 造物投诉科 | 第 3 章 · 造物审计 |
|---|---|---|---|
| **调式** | D 宫（D E F♯ A B） | A 羽 ↔ C 宫 **交替**（羽宫互换=「不对劲」的笑点来源，不制造恐惧） | D 羽（D F G A C），四度偏低 → 明暗摇摆 |
| **和声推进** | D → Bm → G → A，四小节一轮，**每次都解决** | ii–V 反复，**故意不解决**（挂住） | 低音持续 + 五度堆叠，无功能进行、无解决 |
| **拍速** | ♩= 60–66 `[待实]` | ♩= 76–84 `[待实]` | ♩= 88–96 `[待实]`（慢慢来：72） |
| **节奏密度**（每小节发音数） | 1–3 个，大段休止（留白 > 声音） | 1 个脉冲 + 每 2 小节一个切分 16 分短簇 | 每拍 1 个低音脉冲（稳定）+ 稀疏高音点 |
| **动机完整度** | 4 音动机 A（上行 2 度 + 跳进），**完整** | 动机 A 的**倒影**（升→降），语序错乱 | 动机 A **砍掉最后一音**（3 音，悬着不落地） |
| **音色重心** | 三角波 + 慢低通 `[待实]` Hz，极柔 | 窄脉宽方波（文具/打字感）+ 玻璃感正弦泛音 + 低音 drone | 正弦 sub（体感）+ FM 短衰减木琴音（公章敲在纸上） |
| **噪声层** | 纸页微风（低通噪声，几乎听不出） | 办公室底噪 + 极轻翻页点缀 | 翻页 + 低频滴答层（**仅沙漏运转时存在**） |
| **旋律自由度** | 高（动机音可跳音区） | 中（必须回到主音附近） | 低（级进，不许跳） |
| **情绪基线** | 好奇 · 有点呆 · 温暖 | 官僚 · 滑稽 · 憋一口气 | 克制 · 有秤砣 · 底下藏温柔 |
| **一句话** | 「一张安静的纸」 | 「一台坏了的饮水机」 | 「一支正在称重的笔」 |

**章节切换点**：`sfx_stamp`（章末盖章）→ 0.3 s `[待实]` 静默（换场呼吸）→ 新章从第 1 小节淡入。旧章等功率交叉淡化退出。**禁止硬切**。

### 2.3 反重复策略（8 条，针对「循环一会儿就听腻」）

| # | 手段 | 落地做法 |
|---|---|---|
| 1 | **没有循环素材** | 无 loop 段。调度器每小节点生成音符，永不重播同一段音频。 |
| 2 | **动机变形而非重播** | 4 个变形集（原形/倒影/缩短/加花），每 2 小节加权随机取一个。 |
| 3 | **洗牌袋选句法** | 4 个和声进行做成 bag，洗牌后依次取，同一进行不连续出现。 |
| 4 | **休止符优先** | 每小节至少 1 个八分休止。安静比音符更抗疲劳。 |
| 5 | **人味微扰** | 每音 onset ±`[待实]` ms、音高 ±`[待实]` cent、音量 ±`[待实]` dB。人耳对「完全对齐」最敏感。 |
| 6 | **16 小节级分层呼吸** | 噪声层每 16 小节进/出一次；pad 低通截止做 30 s 级慢扫。玩家感觉不到循环，只感觉空气在变。 |
| 7 | **事件应答（call & response）** | 第 1 章：每次造物成型，BGM 回一个高八度应答音。**非周期**变化，主角每画都不一样。 |
| 8 | **卡关降密兜底** | 单章连续停留 > `[待实]` 分钟（玩家卡住），BGM 自动去掉动机层，只留垫音 + 低音。声音变稀 = 「没人催你」，不靠重复维持存在。 |

### 3.3 能力音：5 个音色家族 × 3 个根音变体（不做 24 个独立音）

> 24 个能力逐一做音，会在 6 天内变成 24 个互相打架的噪音。方案：**家族定音色，根音取本关调式的 3 个音随机变体**。玩家听不出「24 个声音在吵」，但听得出「这一类是一家人」。

| 家族 | 24 个能力的完整归属（**穷举，无遗漏**） | 音色特征 | 关内落位检查 |
|---|---|---|---|
| **硬**（实心撞击） | 变硬 · 变重 · 无限长 · 防水 | 低频 + 强分音 + 极短衰减（「实心」） | 关1 / 3 / 4 / 6 / 7 / 8 / 9① / 9② / 9③ |
| **轻**（飘 / 慢） | 变轻 · 反重力 · 时间慢 · 倒转 · 会跳 | 高频上滑 + 气声噪声（「飘」） | 关4 / 7 / 8 / 9① / 9② / 9③ |
| **滑**（流动 / 黏合） | 会滚 · 滑 · 黏 · 吸水 | 低频颤音或滑音（「流动」） | 关2 / 3 / 5 / 6 / 7 / 9① / 9③ |
| **声 / 光**（无形） | 会说话 · 发光 · 透明 · 复制 | 正弦泛音群 + 长衰减（「无形」） | 关5 / 6 / 7 / 9① / 9② / 9③ |
| **活性**（有脾气 / 有能量） | 可燃 · 导电 · 磁 · 怕痒 · 记仇 · 饿 · 一刀切 | 噪声爆裂 + 断奏 tick（「活性」） | 关4 / 6 / 8 / 9③ |

| 关 | 芯片 | 家族分布 | 覆盖 |
|---|---|---|---|
| 1 | 变硬 | 硬×1 | 1/5（单芯片关，无问题） |
| 2 | 变硬 · 会滚 | 硬×1 滑×1 | 2/5 |
| 3 | 变硬 · 会滚 · 变重 | 硬×2 滑×1 | 2/5 |

| 场景 | 处置 |
|---|---|

| 用户全静音 | BGM+SFX+语音全停；所有声音承载的信息（成功/失败/盖章/提示/机关）必须有画面替代，**不得造成信息缺失** |

## 五、触发策略与工程约束

### 5.1 音频图（主链）

```
osc / noiseBuf ─> gainEnv(ADSR) ─> biquad ─┬─> busBGM   ─┐
                                           ├─> busSFX   ─┼─> masterGain ─> DynamicsCompressor ─> destination
                                           └─> busVOICE ─┘
speechSynthesis（独立于 WebAudio）──onstart/onend──> busBGM.setTargetAtTime()
```

| 节点 | 规定 |
|---|---|
| master 峰值 | ≤ −1 dBFS `[待实]` |
| 长时间平均响度 | `[待实]` LUFS（手机小喇叭能听清 BGM 但不糊 SFX） |
| Compressor | threshold / ratio / attack / release 全 `[待实]`；唯一目的：防多音叠加削波（单文件交付最易翻车处） |
| 并发上限 | 同时发声节点 ≤ `[待实]`（建议 12）；超限**丢弃音量最低的 SFX**，绝不丢 BGM 与语音 |
| 同 id 重触发 | ≥`[待实]` ms（建议 30）；碰撞音额外**每帧 1 个** |
| 调度 | lookahead scheduler：`setInterval` 25 ms / lookahead 120 ms `[待实]`；**禁止用 setTimeout 直接排音符**（抖动=节奏散） |
| 后台 | `visibilitychange` → `ctx.suspend()`；恢复 → `resume()` 并从**当前小节**继续，不从头 |
| 采样率 | 跟随 AudioContext 默认（通常 48 kHz），不强制转换 |
| 依赖 | **不引入 Tone.js**。裸 WebAudio 覆盖三层 BGM 调度 + 24 个 SFX，约 `[待实]` 行。理由：单文件 + 体积 + 6 天工期，抽象层反增调试面。**此条交 tech-architect 复核** |

### 5.2 Ducking（说话时压音乐）

| 参数 | 值 |
|---|---|
| 触发 | `onstart` → 压；`onend` / `onerror` / `cancel` → 恢复 |
| BGM 压低量 | `[待实]` dB（建议 −9 ~ −12） |
| SFX 压低量 | `[待实]` dB（建议 −3，几乎不压；音效是玩法信息，不能消失） |
| 起音 / 释放 | `setTargetAtTime`：起音 `[待实]` ms（建议 60）、释放 `[待实]` ms（建议 250）。**禁止直接赋值 gain**（爆音） |
| 气泡模式 | 同样 ducking（气泡也算「有人在说话」），压低量减半 `[待实]` |
| 兜底 | `onend` 未触发（部分浏览器 bug）时，按 `duration + [待实]` ms 超时强制恢复 |

### 5.4 每局语音额度（防唠叨的唯一硬闸）

| 闸 | 上限 `[待实]` | 说明 |
|---|---|---|
| 单句时长 | ≤ `[待实]` ms（建议 4000） | 超长只走文字（≤18 字已基本覆盖） |

| 同句整局重播 | ≤ **2 次**（v2 9.1 合同值） | 音频侧实际取 **1 次**（更严，袋空即静音） |
| 单关条数 | `[待实]`：普通关 **2** / 终局关 **4** | 开场 + 首次成功（+ 关9 终局 2） |
| 单局条数 | `[待实]`：**≤ 30 条** | 全流程计划量 ≈ 23–27 条 |
| **单局累计发声时长** | `[待实]`：**≤ 75 000 ms（75 秒）** | ≈ 22 分钟局的 5.7% |
| 超闸行为 | 达上限后**全部语音静音**（只留气泡），直到新开一局。**不做「已达上限」提示**（提示本身也是唠叨） | — |

**密度实测（这是本版最重要的一个风险判断）**

| 账 | 数 |
|---|---|
| 第 1 章 3 关：5–7 分钟，语音 = 3 开场 + 3 首次成功 = 6 句 | **约每 60 秒 1 句** |
| 关 1 开箱：0–3 s「你是谁？」+ 22–28 s「能踩。它没抱怨。」 | **25 秒内 2 句** |
| 第 1 章之后（关 4 起每关约 2.4 min，语音 2 句） | 约每 72 秒 1 句 |

**结论**：句数密度比我 v1 设的闸更密（v1 是每局 16 条）。**这不构成违规——v2 的 9 关各 2 句是「一次性首次」语义，不会复发，实际听感是稀疏的。但第 1 章 + 关 1 开箱这一段是 D4「不能唠叨」最可能翻车的地方**，因此追加 5 条执行约束（不改台词、不改时机；丢弃顺序按 `levels.md` 9.1b 的信息量排序，本处只落实执行细则）：

| 约束 | 做法 |
|---|---|
| C1 | 关 1 开箱保留 2 句（它是开箱，必须让人立刻知道「这游戏有声音」），但**第 2 句必须等盖章演出结束之后再起**，且 ducking 全量生效。**C1 是 C4 的唯一豁免**。 |
| C2 | 关 2 / 关 3 的开场句**延后**到画面稳定 `[待实]` ms（建议 3000）后起播，不与上一关成功句撞车；两句间隔不足 4000 ms 时**丢弃开场句**（信息可由画面承担）。 |
| C3 | 第 1 章内任意两语音间隔不足 `[待实]` ms（建议 45000）时**按信息量决定丢谁，不一律丢开场**（见下表）。 |
| **C4** | **同一说话人强制间隔 ≥ `[待实]` ms（建议 45000），跨关也算。默认手段是「延后」不是「丢弃」**——语音可以等，没必要为了守间隔而牺牲一句台词。仅当延后会与后续语音撞车（本关已结束 / 首次成功已播）时才丢弃。 |
| **C5** | **说话人不在画面内时不得起播**（B17，黑名单级）。玩家找不到声源会把这句听成系统旁白，笑点立刻变噪音。前置条件：`speaker.onScreen === true` 由主程序提供。 |

**C3 丢弃顺序（按信息量，来自 `levels.md` 9.1b，与设计侧一致）**

| 丢弃顺序 | 句子 | 依据 |
|---|---|---|
| 第 1 个丢 | 关3「你踩不动我。别试了。」 | **零信息**：纯挑衅，画面已写明他踩不动 |
| 第 2 个丢 | 关2「它不肯走。它是方的。」 | **含机制信息**：是关2「形状决定形态」的第一句铺垫，能保就保 |
| 不丢 | 关1 两句 | 开箱声音锚点（C1 豁免） |

> **原始判断修正（记录在案）**：我第一版写「里程碑优先于氛围」，隐含假设「所有开场句都是氛围」。**这个假设是错的**——关2 的开场句在教机制。因此 C3 从「一律丢开场」改为「按信息量丢」，并新增 C4 处理「同一说话人连响」这一真正影响听感的维度。

**密度要按「同一个声音出现几次」算，不是按句/秒算（设计侧指出的关键修正）**

| 第 1 章 6 句的实际声源分布 | 连响风险 |
|---|---|
| 关1 开场 农夫 + 关1 首次成功 农夫 | **同一声音 25 s 内 2 次** → C1 豁免，靠「第 2 句延到盖章后」拉开 |
| 关2 开场 农夫（紧接关1 农夫成功句） | **跨关同一声音** → C4 生效：**延后**至 45 s 门槛后再播，不丢弃（此句含机制信息） |
| 关2 首次成功 农夫 | 与上句间隔通常已 >45 s |
| 关3 开场 **水泵** + 关3 首次成功 **水泵** | 同声音 2 次，间隔通常已 >45 s；不足时 C4 延后后者 |

> 结论：**第 1 章真正的连响只有一处——关 1 到关 2 的农夫三连**（设计侧指出的点）。C1 + C4 合起来解决它，无需删任何一句。

### E.1 对外 API（名字由 tech-architect 定，音频侧照此实现）

```

                            // 解锁前：play 排队（≤3，只排 pendown/spawn），speak 直接丢弃
```

### E.2 碰撞音聚合：物理侧做，音频侧只做「假设每帧最多被调用一次」

**两处认知纠正（我原方案写错了，记录在案）**

| 我原来的写法 | 实际 |
|---|---|
| 「matter 一次 `collisionStart` 一帧内可能吐十几个 pair」 | **`collisionStart` 是一次事件带一个 `pairs[]` 数组**；真正的压力来自「一帧最多 3 个物理子步」→ **一帧最多 3 次 `collisionStart`**。要聚合的是**跨子步**，不是跨事件 |
| 「按冲量取大者」 | **`pair` 里没有冲量字段**，matter 不暴露 impulse。必须自己算代理量 |

**代理冲量公式（物理侧算，音频侧不重复实现）**

```
vRel  = dot(vB − vA, normal)     // 法向相对速度
mEff  = mA·mB/(mA+mB)            // 约化质量
score = |vRel| · mEff            // 代理冲量
```

> 为什么必须物理侧算：只有物理侧同时握着**同一时刻**的速度与法线。音频侧拿到的是事件对象，异步处理时速度已变，算出的 `score` 是错的。

| 责任 | 归属 | 具体 |
|---|---|---|
| 收集 + 算 `score` | **物理侧** | `collisionStart` 内只收集，**帧末**（不是子步末）取最大值 |
| 闸门 | **物理侧** | `score > impactMinScore` `[待实测标定]`；同 `bodyId` 冷却 **90 ms** `[待实测标定]` |
| 回调 | **物理侧** | `PhysicsWorld.onImpact(cb)`，**每帧最多 1 次**，载荷 `{score, material, bodyId}` |
| 音量映射 / 音色 / 并发节点上限 | **音频侧** | `sfx_collide` 的 bandpass 中心 = f(score)，见 附录 B |

**音频侧唯一需要遵守的事**：假设每帧最多被 `onImpact` 调用一次，不做去重、不做时间窗取最大。

**这道闸门修的不是音量，是「石头掉下来但没响」**：静置接触与滚动会反复触发 start/end（matter 接触状态抖动），无闸门时并发节点会在 1 秒内被打满，随即触发优先级丢弃逻辑 → 玩家听到的是漏音，不是噪音。

### E.3 `impactMinScore` 标定流程（音频侧负责出数，物理侧负责给可调环境）

| 项 | 规定 |
|---|---|
| 环境 | 物理侧提供 `?impactDebug=1` HUD：实时显示本帧 `score` 与是否被闸门拦下 |
| 场景 | **关 8**（深度预判关，坠落与弹回最密集） |
| 判据 A「落地必响」 | 造物从本关最高点自由落体首次触地的那一帧，`score` **必须**通过闸门 |
| 判据 B「静置无噪音」 | 农夫/造物静置 **5 s** 内，`onImpact` 回调次数 = **0** |
| 取值方法 | 阈值设为「判据 A 实测 score」的 `[待实测标定]`（建议 0.4–0.5 倍），再往上抬到判据 B 刚成立为止 |
| 回填位置 | `materials.js` 的 `impactMinScore`（物理侧文件，我出数、他回填） |
| 责任标注 | 主程序 + audio-director 共同标定，挂在阶段 2 待实测项 |

### E.4 语音降级窗口：「不重试」的精确含义

| 项 | 规定 |
|---|---|
| 保留 | `voiceschanged` 窗口 **1500 ms** `[待实测标定]`（Chrome 桌面首次必返空数组，砍到 0 会让桌面 Chrome 白白降级） |
| **不重试的定义** | **不做「事后补播」**。窗口内可用 → 后续台词用语音；窗口内不可用 → **当场已经走了气泡的那几句，绝不回补** |
| 为什么 | 否则会出现更糟的体验：玩家已读完气泡，1.4 s 后系统把同一句念出来 |
| 窗口影响范围 | 只影响「**未来**的 utterance 是否用语音」，不影响已发生的 |
| 状态锁定 | 窗口结束（无论成功/失败）后 `VoiceService` 状态**锁定，不再变** |
| 渲染顺序铁律 | **气泡永远先渲染，语音是附加的。** 不许出现「等语音就绪再显示文字」 |

> 这条对 4.5 双层台词的执行含义：**语音模式**下不显示短版气泡（避免边读边念），**气泡模式**下短版气泡先出、语音不存在。两种模式互斥，不存在「先气泡后语音」的中间态。

### E.5 调度时钟与后台（两条性能红线的补充）

| 项 | 规定 |
|---|---|
| 计时源 | **必须用 `AudioContext.currentTime`**，不许用 `performance.now()` 累加——后者与音频时钟会漂移 |
| `document.hidden` | 降低调度密度或直接停 BGM 调度 |
| 切回前台 | 用音频时钟**对齐到当前小节**，**禁止一次性补发漏掉的音符**——那是「开后台回来听到一串快进的音乐」的成因 |
| `OfflineAudioContext`（程序混响 IR） | 若做，**必须在首帧之后 idle 时生成**，不得阻塞 tech-baseline P9 的「2.5 s 首次可交互」门禁。此条在 5.5 已列为**最先砍**的 P2 |
| 节点泄漏 | 复用 `AudioBuffer` 之外，**每次播放的节点必须 `stop()` + `disconnect()`**。节点泄漏不涨内存、涨 CPU，表现为「玩十分钟后开始卡」，比新建 buffer 更隐蔽 |

### E.7 第三轮补充（契约已 FROZEN：baseline v1.1）

| # | 项 | 定稿 |
|---|---|---|
| 1 | **`onImpact` 的注册方式**（数据流物理→音频，但注册动作音频→物理） | 音频侧在 boot 里**订阅一次**：`PhysicsWorld.onImpact(evt => AudioBus.play('sfx_collide', evt))`。依赖因此是单向的（audio 依赖 physics，physics 不 import AudioBus），不会出现「物理回调音频、音频又反调物理」的环。**修正 E.1 里把 `onImpact` 列进 AudioBus 的写法** |
| 2 | **`mEff` 遇静态体必须 `mEff = mA`** | 静态体质量是 `Infinity`，直接代入会得 `NaN` → **从第一次地面接触起污染整个 score**，表现为「所有碰撞音变成默认音量或静音」。这条虽是物理侧实现，但 `score` 的消费者是音频侧，故登记在此 |
| 3 | **`suspend()` 与 `stop()` 是两条路，绝不可混用** | 见下表。混用的结果：`stop()` 后再 `resume()` 得到一张**空图**——静音、不报错、无任何异常日志 |

**两条关停路径的正确用途（这是我上一轮的漏洞：只想了 `stop()` 一条）**

| 路径 | 对节点图的影响 | 重开时 | 用途 |
|---|---|---|---|
| `ctx.suspend()` / `resume()` | **保图**（节点与连接全部保留，音频线程停止处理） | 直接 `resume()` 即恢复，**不需要重建** | **日常关声音**（`setEnabled(false)`）/ 页面隐藏。CPU 同样省下来了，且无重建成本 |
| `stop()` + `disconnect()` | **拆图** | 必须**重建全部源节点**，否则空图 | 只用于「彻底释放」（长时关闭、内存吃紧）。**不要用它做日常静音** |

> **推荐实现**：`setEnabled(false)` → `suspend()`；`setEnabled(true)` → `resume()`。日常操作绝不走 `stop()`，因此**没有「重建 BGM 引擎」这个需求**，省掉一整套生命周期代码。`stop()+disconnect()` 只留给节点回收（每个 SFX 播完自清理），两者职责不同、不要合并。
>
> `suspend()` 路径的唯一注意点：**iOS Safari 在 `resume()` 时可能需要手势**。所以 `resume()` 若被拒绝，不要报错、保持 suspended，等下一次 `pointerdown` 再试（与 E.1 的「解锁失败不重试」同一策略）。

|---|---|---|
| 4 | **程序混响正式砍掉，不留** | 5.5 的 P2 清单里「程序混响 IR」一项**直接删除**（不是"最先砍"，是"不做"）。纸感混响若需要，用「噪声层 + 短衰减」在 **SFX 侧近似**，不进 BGM 链。理由：`OfflineAudioContext` 的 idle 时机在低端机可能落在帧率恢复期，正好与最坏的物理场景撞车 |

### E.8 碰撞音标定：去抖升为前置必做 + 未标定的降级退路

| # | 项 | 定稿 |
|---|---|---|
| 1 | **pair 级去抖：P1 起必做，且先于阈值标定** | 键 = `min(idA,idB) + max(idA,idB)`，同一对刚体 **200 ms** `[待标定]` 内重复的 `collisionStart` 丢弃。**不是"B 判据达不到 0 才启用的补丁"，而是消除测量污染的前置工具**——用被污染的分布定阈值，定出来的数在任何实现下都不对，与阈值高低无关 |
| 2 | **标定顺序（写死，不许调换）** | ① 先去抖 → ② 看 `score` 分布 → ③ 最后定 `impactMinScore` |
| 3 | 反序的因果链（给排查用） | 先定阈值 → 拿到被抖动的分布 → 阈值偏高 → 症状「轻碰撞没声音」 → 极易误诊为「配方表增益写太小」→ 回头改配方 → 越改越错 |
| 4 | **未标定时的降级退路（不许拿估算值上线）** | 若到阶段 3 仍未标定完，**碰撞音降级为固定音量**（`score` 不影响增益，只用 `material` 选音色），待标定后再开映射。带一个错阈值进发布，比暂时不做映射更糟 |
| 5 | 责任与时间点 | 两项标定（`impactMinScore`、语音 45 s 冷却）均在阶段 2 末，而那时主程序通常在赶关 4–9。**tech-architect 会在阶段 5 打包检查时主动核对这两项是否已标定** |
