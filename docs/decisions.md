## D1 主循环 = 关卡剧本制为主，沙盒作为通关奖励 【已定 · 2026-10-26】

**决策**
- 主线是**章节式关卡解谜**：每关给一个"缺了什么"的困境，玩家用造物补上才能过；难度曲线靠章节递进承载。
- 全部章节通关后解锁**自由沙盒**（复用同一套造物系统，成本近似为零）。
- 不做「剧情编辑器」。玩家自由度的载体是**每关 1 个自由造物槽**：同一个缺口，造桥就是桥的剧情，造鸟就是鸟的剧情 —— 由系统按"造物属性 + 能力标签"组合出台词，而非玩家写剧本。

**理由**
1. "按预定义脚本通过 + 从易到难 + 适合任何年龄"三条需求，只有关卡制能同时满足；沙盒没有难度曲线这个概念。
2. 纯沙盒的真实缺陷不是不好玩，是**旁观者 30 秒看不懂在玩什么**。参赛作品必须可演示，关卡自带白话目标。
3. 沙盒作为奖励，既满足"自由"的心理需求，又不增加系统成本。

**代价**：需要设计 8–12 个关卡（阶段 3 的主要工作量）。

**待复核**：关卡数量、章节划分、自由造物槽的台词生成规则 → 游戏设计总监。

## D2 造物实体化 = 形状即物理（A 方案）【暂定 · 2026-10-26 · 用户未复核】

**决策**
- 系统**不做语义识别**。手绘笔画只提取几何属性：长度、闭合性、面积、重心、笔画数 → 映射为物理形态（梁 / 容器 / 轮 / 团块 / 绳）。
- **能力**（预定义芯片点选，或文字输入关键词组合）改变的是**行为规则**，不是物理形态。
- **命名只影响外观与台词**，不影响物理与判定。玩家可给物体起任意名字，系统只用来生成演出文本。
- 文字输入 = 「修饰词 + 名词」两段关键词匹配，词表 40–60 个，纯前端；**不接大模型**。未命中走吐槽兜底，未命中本身作为幽默点。

**理由**：容错（几何判定永不出错，语义判定必然误判手绘）／差异化（同类三者都是"系统已知道那是什么"，本作反之）／幽默由机制自发生成。

**风险**：用户尚未在 A/B/C 中明确选项，本决策为默认采纳，若用户改选 B/C 则 D2 作废重排。

## D4 音频三层：BGM / SFX / 语音，全部零素材【已定 · 2026-10-26 · 用户硬要求】

- **不允许音频文件**。BGM 与 SFX 全部 WebAudio 程序合成；语音用 Web Speech API `speechSynthesis`（zh-CN）。
- 语音只出现在**情绪高点**（章节开场、首次过关、盖章、终局），教程一律纯文字。
- 三条硬约束：① 无中文语音时降级为「文字气泡 + 音效」，不得静默失败；② iOS 需用户手势解锁，首次点按画布时释放无声 utterance；③ 声音开关常驻可见。
- 连带约束：供朗读的台词 **≤18 字**（已并入变更单 R4）。

## D7 裁定 R5：关1「绳」不构成死路【已定 · 2026-10-26】

**争点**：附录 A 判定改为有序（先判"笔画数≥2 且首尾相连 → 绳"），会先于"长宽比>6:1 → 梁"命中。玩家用两笔画出关1 的桥就会被判成绳，绳若不能承重即死路（手绘不可避免，很常见）。

**裁定**：关1 不改设计，理由如下——
1. 能力「变硬」的定义就是"碰撞形变系数置 0、可承载重量"。**绳只是拓扑，不是材质**；绳 + 变硬 = 刚性链，等价于多段梁，能承重是**从能力定义推出来的**，不是待标定项。
2. 关1 只露出「变硬」**一个**芯片，不存在"选错能力"的分支。死路只可能来自形状被判成绳，而绳+变硬可解，闭环成立。
3. 若实测中绳+变硬仍撑不住，**按实现缺陷回主程序修**，不改关卡设计——这是判据归属问题，不是设计问题。

**连带规则**：任何"单能力下的死路"投诉，先查该能力定义是否被正确实现，再谈改关卡。

## D8 音频 v2 与第 1 章密度裁定【已定 · 2026-10-26】

**规格路径变更**：有效文件为 `docs/audio-spec-v2.md`；`audio-spec-v1.md` 降为作废跳转页。后续任何人只许引 v2。

**争点**：第 1 章 3 关 5–7 分钟内 6 句语音（3 开场 + 3 首次成功），关 1 前 30 秒有 2 句（0–3s「你是谁？」+ 22–28s「能踩。它没抱怨。」）。音频侧提出 C1——把第 2 句延到盖章演出之后。

**裁定：驳回 C1。** 理由：这两句是 30 秒钩子的两个支点，不是重复信息。「你是谁？」负责好奇，「能踩。它没抱怨。」负责**即时兑现**——延迟它等于把"我画的东西真被用了"的奖励感从成功瞬间挪走，而这正是要命的那一下。

**改为执行级约束（不改台词、不改时机）**：
- **A1** 第 2 句必须在盖章音效**之前**完整念完；剩余时间不足则**丢弃第 2 句、只留盖章**。宁可少一句，不许叠音。
- **A2** 接受 C2：关 2/3 开场句延后至画面稳定 3 秒后；与成功句间隔不足 4 秒则丢弃开场。
- **A3** 接受 C3（限第 1 章）：同章内两句间隔不足 45 秒时，**弃「开场」保「首次成功」**——里程碑优先于氛围。

**两条架构归属（由制作人直接裁定，不再开会）**：
- `AudioContext` 由 audio 模块**单例持有**，是唯一 owner；其他模块只调 audio 对外暴露的 4 个方法，禁止自行 `resume()`。
- 碰撞音由物理层**每帧取冲量最大者**再回调，SFX 每帧最多 1 个碰撞音——matter-js 一帧可吐十几个 pair，照单全收会糊成噪音墙。

| 项 | 裁定 |
|---|---|
| 未解锁前 `play` 行为 | **采纳排队**（长度 ≤3，只排 `pendown` / `spawn`），不采纳"静默丢弃"。理由：首帧最可能触发的是落笔纸声，丢掉的表现就是"玩家画第一笔没声音"——评审看到的就是"声音没做"。同时 `unlockMedia()` 仍走首次 `pointerdown` 的**同步**路径，把窗口压到最小 |

| 立体声定位 `x` | 标 **P2 可砍**；同时带 panner 的 SFX **≤2**，只给环境音（沙漏/水/火/岩浆/感光）；`collide` / `pendown` **永不加 panner** |

### 3. C5 说话人必须在画面内 —— 兜底默认值

`onScreen` 判定拿不到时**默认 true**。宁可偶尔飘来一句，也不要让一句台词永久消失。关3 水泵若做成纯 HUD 图标，由设计侧改触发点或把台词挪到首次踩踏板失败之后。

### 4. 记两个技术事实（防后人重犯）

- matter 的 `collisionStart` 是**一次事件带 `pairs[]` 数组**；压力来自**一帧最多 3 个物理子步**，要聚合的是**跨子步**，不是跨事件。
- **`pair` 没有冲量字段**。照 `pair.impulse` 写不会报错（读到 `undefined`），表现是"所有碰撞音音量一样"，会被误判成映射曲线问题。必须用代理量 `score = |vRel·n| × mEff`，并对静态体 `mass=Infinity` 导致的 `mEff=NaN` 兜底。

## D12 复制体的能力继承规则（推翻技术基线 §6 的通则）【已定 · 2026-10-26】

**争点**：技术基线 §6 写「复制体不继承能力」作为通则。若照此施工，**关7 解法②（团块 + 复制 + 黏 → 三块自焊台阶）直接废掉**——复制体不继承黏，就成 1 块会黏 + 2 块不会黏，台阶焊不住。关7 从 3 条正解掉到 1 条，**违反 R1 裁定**；关9 阶段三的第三条路同理。

**裁定（采纳游有方方案）**：
- 复制体**继承「除复制本身以外的另一枚能力」**；
- 复制体**不继承复制，且不触发链式复制**。

**理由**：递归风险由「禁止链式复制」这一条挡住就够了，不需要用「不继承」去挡——后者是拿大炮打蚊子，顺带把两条正解一起打死。

**归属**：`tech-baseline-v1.md` §6 需按此改；`levels.md` 第三节「复制」行已标注后果。此类"通则顺手杀掉某关解法"的问题，以后一律先 grep 全部关卡解法再定通则。

## D13 D12 补全：复制体出现在哪、以什么形态出现【已定 · 2026-10-26】

**问题**：D12 只定了「复制体继承另一枚能力」，没定**3 个复制体生成在哪**。原写法「在原位额外生成 2 个」+ 黏 = 当场焊成一坨，关 7 解法②依然不成立，只是失败方式更隐蔽（不是散开，是粘成球），且不报错、会被归因成"物理参数没调好"。

**裁定（2026-10-26 修订：原「造物宽度 × 1.2」作废）**：
- `复制 + 黏` 组合命中时，三块**共享边、一次 `Body.create({ parts })` 生成**，当帧即为 1 个复合刚体（预焊）——不需要间距、不需要闭合速度、不需要 300ms 等待。**这是两轮讨论压平后的最终实现，代码反而少一半。**
- 非 combo 的接触焊接路径：**紧贴生成（接触距离内）**，具体像素由技术侧按 `tech-baseline §6` 标定。`宽 × 1.2` 作废的理由：`黏` 是「接触瞬间焊死」，0.2×宽 的缝让三块水平速度为 0 时**永远接触不到**，黏一次都不触发；失败现象是"我点了黏它没黏"，**比粘成一坨更难查**（像能力没写对，不像参数问题）。
- 验收判据（改为可测）：3 个独立刚体生成瞬间**互不重叠** → 300ms 内焊成 1 个复合刚体（顶层 body 数 = 1、parts ≤ 24）→ 两端搭岸 → 两次跳跃内通过。原判据「3 块互不相连 → 焊接后形成阶梯」自相矛盾（不接触就不焊），作废。
- 治理条款保留：**排列与系数由设计给定，实现只负责标定，主程序不得自选。**
- 归属条款补充：**归属方给出不可实现的数，同样要自己收回**——一个数不会因为写在裁定里就变得可实现。

**通则（进 D 系列，供以后所有能力设计复用）**：

## D15 施加冲量的能力统一 `J = k × mass`（A 方案）【已定 · 2026-10-26】

**背景**：`怕痒` / `会跳` / `记仇` / `反重力` / `会滚` 五个能力本质都是「给刚体施加一次冲量」。固定冲量时，画得大的孩子弹不上四倍高台——**这条 bug 2026-10-26 已实证过一次**。

**裁定**：
- 五个能力**统一用 `J = k × mass`（即固定 Δv）**，**只标 `k`，不标 J**。
- 否决 `mass^0.7`：面积差 2 倍时 Δv 差 19%，够让"画得大的孩子过不了关"。这条的取舍是**判据可写**压过"更物理"。
- 验收：面积差 2 倍的造物，**Δv 相差 ≤5%**。

**连带（必须保留，不许删）**：`变轻` 对弹射类能力是**天然 no-op**（J 与 m 同比缩放、Δv 不变），这是 A 方案的必然结果，**不是叠加失效**。因此——
- 关4 把 `变轻` **升级为「对照组」**：贴了两个芯片什么都没变 → 学习点变成"配对要贴对，不是贴得多"。这个教学点比原来的"更高"更有价值。
- **任何人不得以"技术上是 no-op"为由删掉这个对照组**，也不得为让它"有点用"去增强弹射（那会把冲量改回固定值，坑原样复现）。
- **关4 解法④（变轻 + 怕痒 → 弹更高）正式作废**，9 关无其他路径依赖它。

## D16 「会滚」必须保摩擦、降阻尼（否决 friction=0 版本）【已定 · 2026-10-26】

**争点**：`会滚` 若按摩擦特性实现成 `friction = 0`，它其实**不会滚**——摩擦归零的圆体失去 traction，既不转，遇 ≥5px 台阶还彻底卡死。这是**名字骗人**，比"死芯片"更糟：玩家会记住"这游戏的说明不可信"。

**裁定**：
- `会滚` = **保持 friction 不变、降低阻尼**（`frictionAir` 下调 / 角速度衰减下调）。
- 效果：**只对圆有意义**——圆滚得更远、遇缓坡持续加速；长条与团块本来就没有"滚"这回事，贴了也没变化。这正好是「形状决定形态」的延伸课。
- **若 matter 无法表达"保摩擦降阻尼"，必须回报，不许静默退回 `friction = 0`。**

**连带三处（此前悬着，现全部保住）**：
| 位置 | 结论 |
|---|---|
| 关2 ④ | 从"陷阱"改为**正解变体**：轮 + 会滚 = 滚得更快更远（不再是反例，不再需要"看着有道理但不对"这个台阶） |
| 关3 ③ 滚石反复碾压踏板 | **保住**（靠滚动，不靠摩擦归零） |
| 关8 ④ 闭合圆 + 会滚 + 变重 弹起当跳板 | **保住** |

问题：`levels.md` 里唯一需要**按几何属性分岔**的台词（造物落地时那句），是程序最容易"顺手写一句更好的"的地方。主程序已实际自拟过 3 句。

## D18 D16 验收数据 + 南瓜摩擦债 + 撬杠方向【已定 · 2026-10-26】

**`会滚` = `frictionAirMul: 0.25`，实测通过（`tests/roll.test.mjs` 11/11）**

| 判定项 | 实测 |
|---|---|
| `friction` / `frictionStatic` | 0.05 / 0.08 → **一个数没动** |
| `frictionAir` | 0.02 → 0.005 |
| 8° 斜面 3 秒 | 裸圆 65px / 1.5 rad → 会滚 **100px / 2.9 rad（×1.55）** |
| 同样的长条贴会滚 | 9px → 10px（差 11%）：**"同一能力只在形状对时才有意义"是实测成立的** |
| 被否决路线（`friction=0`） | 平地滑 292px 但**只转 0.08 rad**；斜面上转 0.002 rad。**它是雪橇，不是滚** |

> 这条断言永久留在测试里：以后谁再提"把 `会滚` 做成 friction=0"，先看"真滚应转 11.2 rad"这行。

### 南瓜 `friction: 0` 是遗留债，**立即清理**

`friction: 0` 只服务于已被废弃的"沿坡滑"设计。新关2 三条解（圆滚 / 长条撬 / 团块逐级跌）**没有一条依赖滑动**；而 friction=0 会让南瓜在梁上打滑回内侧，**方向正好反**。
**裁定**：南瓜恢复常规摩擦 **0.4–0.6 `[待实测标定]`**。这属实现债清理，不需要设计侧确认。

### 撬杠：力矩够，但缺抗翻转 —— 方向定为「石台开凹槽」

实测：农夫 1.8kg 压长端，短端 13.45kg 南瓜**确实被抬起**（转角 +28°~+52°，前提支点离南瓜 ≤32px 且梁 ≥200px）；7.5:1 不是墙，梁自重帮了农夫。**真实构型压不成的原因不是质量比，是梁只架在石台上、没有抗翻转能力，一压就翻。**

**方向（不是命令）**：与其新增"防翻夹槽"这个要额外被看懂的构件，**不如让支点本身就是一道浅凹口**——石台上开一条浅槽，梁卡在槽里。视觉上不增加新名词，玩家看到的就是"梁卡住了"。
**在游有方定案前，关2 几何不动**；但南瓜摩擦债先清。
