## 一、同类产品扫描：真正拥挤的是哪一类

### A 类 · 画线即固体（**最拥挤，必须避开正面**）

| 产品 | 机制 | 限制手段 |
|---|---|---|
| Crayon Physics Deluxe（2007，鼻祖） | 画出的形状变成实物，靠重力滚动过关 | 无 |
| Brain It On! / Happy Glass | 画线搭桥、引水 | 墨水长度 |
| Bro draw it（浏览器） | 一笔画成固体，解决物理谜题 | 墨水计量 |
| Draw Logic Puzzle（Y8 Studio，2026-07） | 画平台/滚圆，撞僵尸 | 无 |
| 画 Sprunki 小车（浏览器） | 手绘车身 + 钉轮子，物理开车 | 无 |

**共同机制**：画 → 变成**静态或简单刚体** → 靠重力/碰撞过关。玩家做的是"**补一块挡板**"。

### B 类 · 语义召唤

Scribblenauts（打字召唤）、Doodle God（元素合成）、Draw a Stickman（画→预设道具）。
**共同机制**：系统**已经知道**那是什么，玩家只是在选。

### C 类 · 创世/上帝题材

WorldBox（体素沙盒）、From Dust、Black & White。都是**沙盒**，无脚本、无叙事、无难度曲线。

### D 类 · 1024 造物挑战已提交作品（GitHub/公开渠道可见）

| 作品 | 形态 |
|---|---|
| 修仙识字 RPG | 剧情 RPG + 语文知识嵌入 |
| 麦麦餐厅 | 模拟经营 + MCP 餐品数据 |
| 体素破坏（Teardown 风格） | three.js 单文件 3D |
| 俄罗斯方块 | 街机复刻 |

> **结论：造物/手绘题材在本次赛事里没有被占位，但"画线物理"这个品类在市场上极度拥挤。评审见过太多次"画个坡让球滚进去"。**

## 二、我们的楔子（一句话定位）

> **别人让你画"挡板"，我们让你画"物理法则"。**

A 类所有产品缺的那一层，正是 D2 的**能力系统**：画出来的只是形状，**规则由玩家贴上去**。同类零个产品做这件事。

四条可辩护的差异：

| # | 差异 | 同类的状态 |
|---|---|---|
| 1 | **能力即规则**（24 个规则修改器，可两两组合） | A 类只有"画得更长/更斜"，没有任何规则层 |
| 2 | **画得丑不会死路**（兜底团块形态永远可解） | A 类画错就是重来，玩家挫败 |
| 3 | **有剧情**（实习造物主 / 投诉科 / 审计员三章） | A 类全是无剧情的关卡串，B 类无剧情，C 类无脚本 |
| 4 | **有声音**（BGM + 语音赞美/吐槽） | A 类基本只有点击音效 |

**风险提示**：定位句必须出现在首屏 30 秒内，否则会被归类成"又一个画线物理游戏"。

## 三、开源复用清单（不重复造轮子）

| 库 | ★ | 协议 | 用途 | 决定 |
|---|---|---|---|---|
| `liabru/matter-js` | 18.5k | MIT | 2D 刚体物理（约束/传感器/复合刚体），支持运行时增删刚体 | **采用** |
| `schteppe/poly-decomp.js` | 468 | MIT | 凹多边形拆凸包 —— 玩家手绘必然凹，matter-js 官方配套 | **采用** |
| `rough-stuff/rough` | 21.3k | MIT | 手绘抖动/双线/纸张质感渲染，美术路线 A 的核心 | **采用** |
| `steveruizok/perfect-freehand` | 5.8k | MIT | 压感笔迹，决定"落笔像不像真的在画" | **采用** |
| `Tonejs/Tone.js` | 14.8k | MIT | 程序化音乐，无版权 BGM | **候选**（体积允许才用） |
| `goldfire/howler.js` | 25.4k | MIT | 音频文件播放 | **不采用**（本作无音频文件，全程序合成） |
| `piqnt/planck.js` | 5.3k | MIT | Box2D 移植 | **不采用**（matter-js 运行时增删刚体更顺手，且自带 poly-decomp 集成） |

体积预算（内联 min 化后）：matter-js ≈ 90KB + poly-decomp ≈ 15KB + rough ≈ 40KB + perfect-freehand ≈ 10KB ≈ **155KB**，远低于单文件交付上限（同类先例：体素破坏游戏单文件 1.66MB 可跑）。

### 必须自己写的部分（没有现成轮子）

| 模块 | 为什么没人做过 |
|---|---|
| 笔画 → 几何属性提取（长度/闭合/面积/重心/笔画数） | 属于本作独创的形态判定 |
| 形状 → 形态分类（梁/轮/团块/容器/绳/颗粒） | 同上 |
| **能力系统**（规则修改器 + 组合矩阵） | 差异化核心，市面无可复用实现 |
| 关卡脚本与提示阶梯 | 内容，不可复用 |
| 语音触发策略（何时说、说什么、如何降级） | 见 D4 |

## 四、D4 音频与语音（用户新增硬要求）

**三层结构，全部无素材文件、零版权风险**

| 层 | 方案 | 说明 |
|---|---|---|
| BGM | WebAudio 程序合成（五声音阶环境垫） | 无音频文件、可随章节转调、体积为零 |
| SFX | WebAudio 程序合成（落笔摩擦/盖章/金属/水/纸响） | 沿用同类项目验证过的做法：噪声 + 滤波器包络即可 |
| 语音 | **Web Speech API `speechSynthesis`**（zh-CN） | 只用于情绪高点：章节开场、首次过关赞美、盖章、终局 |

**语音的三条硬约束（不做就会翻车）**

1. **必须探测可用语音**：`getVoices()` 为空或无 `zh-*` 时，自动降级为「文字气泡 + 音效」，绝不静默失败。
2. **iOS/Chrome 需要用户手势解锁**：首次点按画布时释放一句无声 utterance 完成解锁。
3. **不能唠叨**：语音只在情绪高点出现，教程一律用文字。成人被念三次就会关掉声音——声音开关必须常驻可见。

> 台词因此需要加一条约束：**供语音朗读的台词 ≤18 字**，超长台词只走文字。已并入给游有方的变更单 R4。
